Quick Calc Pad: app map

A one-page guide to where everything lives in your notepad calculator.

Snapshot of commit 4545292 (2026-10-10). The code can change after this, so treat it as a starting point.

The big picture

One static Astro page. A script in the page runs in your visitor's browser: every keystroke, it reads the sheet line by line, rewrites friendly phrases into plain math, calculates with math.js, draws the answers, and saves every tab to localStorage. There's no server and no API. GitHub Pages serves the built files.

The page

src/pages/index.astro and src/styles/notepad.css: tabs, tips, the ruled textarea, results.

The wiring

src/scripts/app.ts: listens for typing and clicks, draws results, tooltips, margin names.

The brains

src/lib/: translate.ts, calculate.ts, rename.ts, suggest.ts. No page code, so the tests can check them.

Memory

src/lib/storage.ts and templates.ts: saved tabs, or the templates on a first visit.

Follow one action: typing “plus 30” under “20% off 80”

Reference route (3 stops)

  1. src/scripts/app.ts → update()
    Runs on every keystroke. It stores the textarea text in sheets[active], saves with saveSheets, then redraws the results and margin names from calculateSheet(pad.value).
  2. src/lib/translate.ts → parseLine() and continueFrom()
    parseLine splits off a name =, turns plus into +, removes $ € £, and notices the line starts with an operator (continues). continueFrom puts the answer above in front: 64 + 30.
    Why “plus 10%” adds 10%

    continueFrom translates the whole joined text, so 200 + 10% hits the addOrSubtractPercent rule and becomes (200) * (1 + 10/100) = 220.

  3. src/lib/calculate.ts → calculateSheet()
    Walks the lines top to bottom, keeping each answer under its name in known. Unknown names are rejected before math.js runs (so cm never becomes a unit), currencies are carried in knownCurrency, and formatNumber rounds to 2 decimals.

A practice to reuse

Write the core idea and a “Later” list before you build, then check every new idea against them.

  • In this project: devpost/scope.md named the core idea (plain-language percentages with reusable answers) and put currency conversion under Later because it needs an API.
  • Evidence it worked: mid-build requests (currency symbols, margin names, plus 30) were each checked against that line and recorded under Revisions in devpost/checklist.md. Symbols-as-labels got in; conversion stayed out. Templates stayed at three, as decided in prd.md › Product Decisions.
  • Next project: before writing code, write one sentence for the core idea and a short Later list. When an idea appears mid-build, ask: does it strengthen the core idea, and can I show it in a one-minute demo? If not, it goes on Later.
